# 1. ОБЗОР ПРОЕКТА

## 1.1 Что это

**AI Pilot** — платформа, где владелец WordPress-сайта управляет контентом через обычный чат с AI-ассистентом. Без админки WP, без сложных интерфейсов — просто диалог.

> Клиент пишет: *«Добавь блок с отзывами на главную страницу»*
> Агент анализирует сайт, предлагает конкретное изменение, клиент подтверждает одной кнопкой → изменение выполнено на реальном сайте.

## 1.2 Три принципа

| Принцип | Суть |
|---------|------|
| **Chat-first** | Единственный интерфейс пользователя — чат |
| **Human-in-the-loop** | Агент предлагает → человек подтверждает (железобетонный инвариант INV-005) |
| **Site-native** | Работает с реальным WordPress через REST API, не с копией |

## 1.3 Роли

| Роль | Кто | Что делает |
|------|-----|------------|
| **Admin** | Евгений | Видит все сайты, управляет системой |
| **Client** | Владелец WP-сайта | Общается с AI, подтверждает действия |
| **AI Agent (Zero)** | OpenClaw-оркестратор | Анализирует, предлагает, исполняет (после подтверждения) |

## 2.3 Поток данных (обычный диалог)

```
Клиент пишет сообщение
  → Web Chat → POST /api/chat/send (JWT)
    → Auth API: проверка JWT → сайт по URL
      → capability profile (кэш TTL 1ч / refresh)
        → сборка system prompt (mode snippet + site context + soul)
          → запрос в OpenClaw Gateway
            → Zero анализирует, при необходимости читает сайт через WP REST API
            → формирует ответ или proposal
          ← ответ
        ← auth-api сохраняет в БД
      ← Web Chat отображает сообщение / карточку
```

## 2.4 Подключение нового сайта (5 минут)

```
1. Клиент ставит AI Pilot Plugin на WordPress
2. В админке WP → "Generate Connect Code" (8 символов, TTL 5 мин)
3. Клиент на chat.pilotsite.ru → регистрация → "Подключить сайт" → вводит код
4. Auth API проверяет код через /agent/verify-code на сайте
   → создаёт site record (url + wp_token) в SQLite
   → запрашивает /agent/capabilities → кэширует
   → сайт появляется в сайдбаре
5. Можно начинать диалог
```

## 2.5 Безопасность

- **JWT:** access 15 мин + refresh 7 дней, rotation, refresh-токены хранятся как SHA256 hash
- **Gateway token:** только server-side env, никогда не уходит клиенту
- **Connect codes:** одноразовые, TTL 5 мин, per-IP rate limit 5/мин
- **Идемпотентность:** SHA256 dedup на action_requests — двойной клик по Approve не создаст дубль
- **WP Plugin:** 17 опций в allowlist (остальные запрещены AI), `admin_email` не отдаётся
- **Web Chat:** DOMPurify на v-html, JWT только в памяти (не localStorage)
- **Human-in-the-loop:** никакие write-операции не выполняются без подтверждения

# 3. АГЕНТНЫЙ РЕЖИМ

## 3.1 Zero — оркестратор

Zero (main-агент OpenClaw) — мозг системы. Возможности:

- **Спавнит субагентов** для конкретных сайтов (`sessions_spawn`, taskName=`site-{siteId}`)
- **Делегирует кодинг-задачи в OpenCode** (exec/PTY, модель DeepSeek V4 Flash)
- **MCP-инструменты:** GitHub (репозитории, PR, issues), Code Index (поиск по коду), SQL (прямой доступ к БД auth-api)
- **WP-скиллы:** разработка плагинов, REST API, блоки, темы
- **Память:** MEMORY.md + daily notes, контекст каждого сайта (soul + memory + structure)

**Жизненный цикл субагента сайта:**

```
1. Рождение: регистрация сайта → system event [system:new-site] → спавн субагента
   (fallback: создаётся при первом сообщении клиента)
2. Жизнь: субагент имеет URL + API-токен сайта,
   читает контекст через /agent/context,
   пишет историю через /agent/memory
3. Задача: субагент предлагает → Zero согласовывает → субагент исполняет
```

## 3.2 Human-in-the-loop (главная механика)

```
Клиент: "Добавь секцию с преимуществами на главную"

1. Zero анализирует:
   → /agent/capabilities (доступные режимы авторинга)
   → /agent/context (текущая структура главной)
   → определяет формат: Gutenberg blocks / classic HTML / AI Pilot Blocks

2. Zero формирует proposal:
   → человеческое описание + параметры (post_id, content, position) + diff

3. Auth API создаёт action_request с idempotency_key (SHA256)

4. В чате карточка:
   ┌─────────────────────────────────────┐
   │ 📝 Предложение изменения            │
   │ Добавить секцию "Преимущества"      │
   │ + <h2>Преимущества</h2>            │
   │ + <p>Быстро, надёжно, удобно</p>   │
   │  [✅ Одобрить]  [❌ Отклонить]     │
   └─────────────────────────────────────┘

5. "Одобрить" → POST /agent/approve/{id} → WP Plugin выполняет
6. "Отклонить" → proposal закрыт, ничего не выполнено
```

## 3.3 Agent UI Cards (интерактив в чате)

Независимая система карточек — не зависит от WordPress-блоков.

| Kind | Компонент | Use case |
|------|-----------|----------|
| `single_choice` | AgentChoiceCard | 2–6 вариантов, один ответ |
| `multi_choice` | AgentChoiceCard | 2–10 вариантов, несколько ответов |
| `confirmation` | AgentConfirmationCard | Yes/No |
| `form` | (future) | Структурированная форма |

**Механика:** Zero вызывает `POST /api/agent-ui/ui-create` → карточка в чате → клиент выбирает → `ui-respond` → карточка закрывается, в ленту добавляются `assistantResponse` + `followUpMessage`.

**Безопасность:** браузер отправляет только `option_id`; исполняемые значения остаются на сервере; TTL 5 мин; resolved-карточка иммутабельна.

## 3.4 Dual-Mode Authoring (работа с любым сайтом)

Система сама определяет, как редактировать контент на конкретном сайте:

| Режим | Условие | Описание |
|-------|---------|----------|
| `aipilot_blocks` | Extension available | Типизированные компоненты + валидация |
| `gutenberg_core` | Default | Core/third-party Gutenberg blocks |
| `classic_html` | Нет block-комментариев | Семантический HTML, shortcodes |
| `builder_managed` | Elementor/Bricks/Divi | Ограниченный доступ: чтение + анализ |
| `readonly` | Нет прав на запись | Анализ, диагностика, рекомендации |

**Принцип:** отсутствие AI Pilot Blocks — нормальное состояние, не ошибка. Сайт без расширения полностью функционален (INV-006).

## 3.6 Системный промпт (правила поведения агента)

Источник правды: `SYSTEM_PROMPT.md` (единый для всех каналов).

1. Отвечать **только про сайт клиента**, ничего не знать про инфраструктуру AI Pilot
2. **Не выполнять действия самостоятельно** — только описать и ждать подтверждения
3. При запросе действия писать конкретно: что создашь, заголовок, рубрика, текст
4. Отвечать по-русски, дружелюбно, без панибратства
5. Не хватает контекста → уточнить, не делать предположений

# 4. БИЗНЕС-МОДЕЛЬ

## 4.1 Ценностное предложение

**Для кого:** владельцы малых и средних WordPress-сайтов (агентства, фрилансеры, малый бизнес), которые:
- не хотят разбираться в админке WP,
- тратят деньги на фрилансеров для мелких правок,
- хотят быстро и безопасно менять контент.

**Что получает клиент:**
- Управление сайтом через привычный чат (как с живым помощником)
- AI, который **понимает структуру именно его сайта** (не generic-бот)
- Безопасность: ни одно изменение не выполнится без подтверждения
- Скорость: подключение за 5 минут через плагин + код

## 4.2 Модели монетизации

| Модель | Описание | Пример |
|--------|----------|--------|
| **SaaS-подписка (основная)** | Тарифы по числу сайтов и лимиту действий | Free: 1 сайт; Pro: 3 сайта, X действий/мес; Business: 10+ |
| **Per-action / пакеты действий** | Оплата за реально выполненные изменения | Пакет 50 action-credits/мес |
| **Агентская модель (B2B)** | Белая метка для веб-агентств: агентство платит за своих клиентов, клиенты видят бренд агентства | Wholesale: 20+ сайтов |
| **Расширения (upsell)** | AI Pilot Blocks, builder adapters, SEO-модуль | Платная установка на сайт |
| **Поддержка/внедрение** | Настройка под нестандартные сайты, кастомные интеграции | Разово |

## 4.3 Структура затрат (COGS)

| Статья | Комментарий |
|--------|-------------|
| **LLM-токены** | Основная переменная затрата. DeepSeek V4 Flash — дёшево; на типовую сессию — копейки. Оптимизация: кэш контекста (TTL 1ч), короткие промпты |
| **Инфраструктура** | VPS ~ небольшая фиксированная сумма/мес, Caddy+Docker — бесплатно |
| **MCP/инструменты** | GitHub, Code Index, SQL — self-hosted, бесплатно |
| **Поддержка** | Human-in-the-loop снижает нагрузку: агент делает 90% работы |

**Ключевое преимущество:** низкий COGS → высокая маржа. Основная себестоимость — токены, которые дешевеют год от года.

## 4.4 Юнит-экономика (оценка)

> Цифры оценочные, для рамки рассуждений.

- Себестоимость типовой сессии (5–10 сообщений, DeepSeek V4 Flash): **единицы–десятки рублей**
- Тариф Pro (3 сайта): потенциально **10–30 $/мес**
- Маржа при масштабе: **85–95%** (при условии фиксированной инфраструктуры)

# 5. ВОЗМОЖНОСТИ РОСТА

## 5.1 Горизонтальный рост (больше сайтов)

- **Канал №1 — агентства:** у одного агентства 50–500 клиентских сайтов. Продать агентству = 50 сайтов разом. Белая метка + панель администратора.
- **Канал №2 — фрилансеры:** раздают клиентам как доп. сервис "управление сайтом из чата".
- **Канал №3 — маркетплейс WP-плагинов:** публикация в wp.org → органический трафик владельцев сайтов.
- **Канал №4 — партнёрская программа:** реферальная скидка за приведённого клиента.

## 5.2 Вертикальный рост (больше ценности на сайт)

| Направление | Что даёт |
|-------------|----------|
| **AI Pilot Blocks** | Типизированные компоненты + валидация — уникальный режим авторинга, повод для upsell |
| **Builder adapters** (Elementor/Bricks/Divi) | Открывает рынок сайтов на билдерах (огромный сегмент) |
| **SEO-модуль** | Аудит, генерация meta, рерайт под ключевые слова |
| **Контент-маркетинг** | Автопостинг по расписанию, рерайт старых постов |
| **Мультиязычность** | Перевод контента через LLM |
| **Аналитика** | Отчёты "что сделано за месяц" — ценность для агентств |

## 5.3 Платформенный рост

- **Marketplace скиллов/шаблонов** — агент умеет "навыки", которые продаются/подписываются
- **Telegram-канал** — управление сайтом из мессенджера (технически заложено, отложено)
- **Open API** — дать сторонним сервисам доступ к agent-функциям
- **Мульти-платформенность** — тот же движок под Tilda, Shopify и др. (архитектура уже абстрагирована через capability profile)

## 5.4 Рост через данные

- Каждая сессия = размеченный датасет "как люди просят менять сайты"
- Можно дообучать модель на своих данных (fine-tuning) — снижение стоимости и рост качества
- Анонимная аналитика по сайтам (какие блоки чаще просят) → продуктовые инсайты

# 6. УНИКАЛЬНОСТЬ

## 6.1 Чем AI Pilot отличается от существующего

| Аспект | AI Pilot | Типичные альтернативы |
|--------|----------|----------------------|
| **Интерфейс** | Чат-first, ноль обучения | Админки, конструкторы, панели |
| **Глубина понимания** | Агент читает РЕАЛЬНУЮ структуру сайта (capabilities, context, scan) | Generic-боты без доступа к сайту |
| **Безопасность** | Human-in-the-loop как инвариант: ни одного write без подтверждения | Автопилоты, которые могут "наворотить" |
| **Совместимость** | Dual-mode: Gutenberg, classic, builders, readonly — работает с любым WP | Решения, требующие своей темы/плагина |
| **Внедрение** | 5 минут: плагин + код, без разработчиков | Интеграции на недели |
| **Интерактив** | Agent UI Cards (choice/confirmation) прямо в чате | Обычные текстовые ответы |
| **Оркестрация** | Субагент на каждый сайт + human-in-the-loop через OpenClaw | Один бот на всё |

## 6.2 Ключевые отличительные черты

1. **Chat-first + Human-in-the-loop** — редкость на рынке: большинство AI-инструментов для WP либо "просто чат без действий", либо "полный автопилот". Мы занимаем безопасную середину.
2. **Capability Detection** — агент сам понимает, что умеет сайт, и не пытается делать то, что нельзя. Это снимает главный страх владельца ("а вдруг сломает").
3. **Dual-Mode Architecture** — отсутствие нашего расширения не ломает продукт. Это снимает барьер входа и делает масштабирование бесплатным (сайт подключается как есть).
4. **Субагентная архитектура** — у каждого сайта свой изолированный агент со своей памятью и Tone of Voice. При росте до тысяч сайтов не будет "каши" в одном контексте.
5. **Низкий COGS** — вся инфраструктура self-hosted на одном VPS + дешёвая LLM. Конкурент по цене может проиграть уже на уровне маржи.

## 6.3 Модель, которую сложно скопировать

Легко скопировать "чат с GPT поверх WordPress". Сложно скопировать:
- **Инварианты безопасности** (INV-001…INV-012), отточенные на реальных аудитах
- **Субагентную оркестрацию** с памятью на сайт
- **Capability Profile + Mode Router** — систему, которая "понимает" любой WP-сайт
- **Накопленный контекст**: датасеты сессий, скрипты деплоя, аудиты, регламенты

# 7. ИНВАРИАНТЫ

Железобетонные правила системы (из ANSS-спецификации). Нарушение = баг.

```
INV-001: Никаких паролей в открытом виде (bcrypt, никогда не логировать)
INV-002: Gateway Token не покидает сервер (только server-side env)
INV-003: Connect Code одноразовый (DELETE после использования, TTL 5 мин)
INV-004: Идемпотентность всех действий (SHA256 ключ, INSERT OR FAIL)
INV-005: Human-in-the-loop для write-операций (Proposal → Approve → Execute)
INV-006: Extension optionality (Core не падает без AI Pilot Blocks)
INV-007: Agent UI независим от WP blocks
INV-008: Браузер отправляет только optionId, не значения
INV-009: JWT только в памяти (Pinia), не в localStorage
INV-010: v-html только через DOMPurify
INV-011: Кэш — временный, сайт — истина (TTL 1 час)
INV-012: Никаких write без capabilities check
```
